# MTL_LHUC 模型改进记录

## 2026-07-20: 新增 MTL_LHUC 模型（DCN+MLP → PLE → 每塔 LHUC + PCGrad + ESMM）

### 一、修改背景

现有精排模型 `DBMTL_LHUC` 的结构为：

```
bottom_mlp ‖ dcnv2 → concat → 共享 LHUC → MMoE → DBMTL relation towers
```

其在排序场景暴露出几个可改进点：

1. **多任务专家层用 MMoE**，任务间存在参数共享冲突，对相关性较弱的任务（如点击 vs 转化）不够鲁棒。
2. **LHUC 为模型级共享门控**，所有任务塔共用同一组 bias 特征与门控，无法为 CTR / CVR 塔分别建模个性化偏好。
3. **多任务 loss 为简单求和**，任务梯度冲突时互相拉扯，影响收敛。
4. **任务依赖仅支持 DBMTL concat**，缺少 ESMM 这种面向 CTR→CVR 转化漏斗的显式建模。

本次改进据此提出新模型 **`MTL_LHUC`**：将特征交叉层保留，把 MMoE 换成 PLE/CGC，LHUC 下沉到每个任务塔（可独立配置 bias 特征），loss 融合引入 PCGrad，并支持无依赖 / DBMTL / ESMM 三种任务依赖可配置。

### 二、模型结构

```
Input Embeddings (feature group)
   ├── bottom_mlp → LayerNorm ─┐
   │                            ├─ concat → [PLE / CGC ExtractionNets]
   └── DCNv2     → LayerNorm ─┘                 │
                                       每任务表示 (CGC 末层)
                                                 │
        ┌────────────────────────────────────────┴─────────────────────────────────┐
        ▼                                                                          ▼
  CTR LHUC 塔                                                                   CVR LHUC 塔
  lhuc_gate(ctr_bias) * in → lhuc_pp_net → mlp → [relation?] → Linear       (同左, 独立 bias 特征集)
        │                                                                          │
        └─ BiasTask (可选, 辅助监督)                                            └─ BiasTask (可选)
        │                                                                          │
   logits_ctr / probs_ctr                                                  logits_cvr / probs_cvr
        │                                                                          │
        └──────────── ESMM: ctcvr = σ(CTR) × σ(CVR) ─────────────────────────────────┘
```

### 三、关键设计

#### 3.1 特征交叉层（DCN + MLP 并行）

照搬 `DBMTL_LHUC` 的并行结构：`bottom_mlp + LayerNorm` 与 `dcnv2 + LayerNorm` 两路在通道维 concat。复用 `tzrec.modules.interaction.CrossV2`、`tzrec.modules.mlp.MLP`。

#### 3.2 PLE / CGC 替换 MMoE

用 `tzrec.modules.extraction_net.ExtractionNet`（CGC 层）堆叠替换 MMoE，构建方式与 `tzrec.models.ple.PLE` 一致：层间维度通过 `output_dim()` 自动传递，末层 `final_flag=True`（不产出 shared 输出）。每个任务塔从末层 CGC 拿到自己的任务专属表示。

#### 3.3 每塔 LHUC（独立 bias 特征）

每个 `LHUCTaskTower` 可单独配置：

- `bias_feature_group`（塔级 string）：声明本塔 bias 特征所在的 **feature_group 名**。该 group 在 config 的 `feature_groups` 块里独立声明（特征可与主 group `"all"` 重叠，embedding 参数共享——见下方说明），运行时由 `EmbeddingGroup` 自动拼成一张 tensor。
- `lhuc_gate`（`LHUCEPGateConfig`）：门控 MLP 隐层；作用为 `rep = rep * LHUCEPGate(bias_embs)`（乘性 EP scale）。`gate_input_dim` = `group_total_dim(bias_feature_group)`。
- `lhuc_pp_net`（`LHUCPPNetConfig`，可选）：逐层门控 MLP，输入维度为本塔 CGC 表示维度，输出维度作为后续 task MLP 的输入；与 `lhuc_gate` 共用同一组 bias 特征。

**取值方式（feature_group 逻辑视图，与 PEPNet 的 `"domain"`/`"uia"` 同构）**：

```python
grouped_features = self.build_input(batch)            # dict[group_name] -> tensor
bias_embs[tower] = grouped_features[self._bias_group[tower]]
```

不再做张量 offset 切片。每个塔的 bias group 互不相同 → 实现"每个 LHUC 塔单独配置 bias 特征"。配置示例：

```
feature_groups {
    group_name: "all"               feature_names: "user_id" "item_id" "mmb_id" "price" ...
}
feature_groups {
    group_name: "bias_is_click"     feature_names: "mmb_id" "item_id"        # 与 all 重叠, 共享 embedding
}
feature_groups {
    group_name: "bias_is_conversion" feature_names: "user_id" "price"
}
mtl_lhuc {
    task_towers {
        tower_name: "is_click"
        bias_feature_group: "bias_is_click"
        lhuc_gate { hidden_units: [64, 32] }
    }
    ...
}
```

#### 3.4 任务依赖可配置（三选一，可共存）

| 模式 | 配置方式 | 行为 |
|------|----------|------|
| 无依赖 | 塔不设 `relation_mlp`、不参与 ESMM | 各塔独立 |
| DBMTL | 塔设 `relation_tower_names + relation_mlp` | `relation_mlp(concat(self_repr, *parent_repr))`，按 `task_towers` 顺序拓扑 |
| ESMM | 模型级 `esmm { ctr_tower_name, cvr_tower_name }` | CTR 塔全量 BCE；CVR 塔无直接 loss，仅经 CTCVR 监督 |

**ESMM 经典语义**：
- `CTCVR = sigmoid(CTR) × sigmoid(CVR)`，对 `ctcvr_label`（默认取 CVR 塔 label）做 BCE，梯度同时回传两塔。
- CVR 塔的直接 BCE loss 被替换为 CTCVR loss，但 loss dict 仍以 CVR 塔的 BCE key（`binary_cross_entropy_<cvr>`）存放 → loss-metric `MeanMetric` 自动追踪。
- `predict()` 额外输出 `probs_ctcvr_<cvr>` 供评估 / 打分。
- CVR 塔 AUC 仍按 `probs_<cvr>` vs `is_conversion` 报告（`init_metric` 不受 loss 替换影响）。

#### 3.5 BiasTask 辅助头

复用 `DBMTL_LHUC` 的 `BiasTask` 机制：每个 bias head 分支自其 `target_tower` 的表示（`task_net[target]`），训练期输出 `y_bias_<name>`（L2）或 `logits_bias_<name>`（BCE/CE），不修改主塔 logits，推理期跳过。

#### 3.6 PCGrad 多任务 loss 融合

**作用范围**：仅 dense 参数（sparse embedding 仍走 `apply_optimizer_in_backward` 的 fused 反向内更新，标准求和梯度）。该决策受限于：sparse 参数无 Python 可见 `.grad`；DDP 多次 backward 会多次 all-reduce。

**算法**（参照 fairseq [PCGrad](https://github.com/chenllliang/Gradient-Vaccine/blob/master/fairseq/fairseq/optim/pcgrad.py)）：对每对任务梯度 `g_i, g_j`，若 `<g_i, g_j> < 0` 则 `g_i ← g_i − (<g_i, g_j> / ||g_j||²) · g_j`，去除冲突分量。

**集成方式**（核心）：
1. `TrainWrapper.forward` 在 `_use_pcgrad` 时返回 **1-D per-task loss 堆叠**（顺序 = `model.loss()` 返回 `OrderedDict` 的插入序），而非求和标量。
2. `TrainPipelinePCGrad._backward`：
   - 用 `torch.autograd.grad(loss_i, dense_params, retain_graph=True)` 提每任务 dense 梯度（**不触发 fused sparse optimizer、不触发 DDP all-reduce**，与 `ParetoEfficientMultiTaskLoss` 同一模式）。
   - PCGrad 投影后求和得到 dense 目标梯度。
   - 真实图 `backward(sum_loss)`：触发 sparse fused 更新 + 单次 DDP all-reduce。
   - 用投影后的 dense 目标（按 `grad_scaler.get_scale()` 缩放）**覆盖** dense 参数的 `.grad`，随后 `optimizer.step()` 用投影梯度步进。
3. `main.py` 收集 dense 参数（`remaining_params + part_optim_params`，即所有非 fused-sparse 可训练参数）注入管线。

### 八、待办与风险

- **PCGrad + FP16 GradScaler**：首版优先 BF16 / FP32；FP16 需在 GPU 实测 `scaler.unscale_` 与 dense `.grad` 覆盖的交互（已按 `get_scale()` 对齐缩放，理论上自洽）。
- **gradient_accumulation_steps > 1** 与 PCGrad 暂不兼容（`_pcgrad_backward` 已断言拦截，因覆盖语义与梯度累积冲突）。
- **DDP 多卡**：`autograd.grad` 不触发 sync，单次 `backward` 触发一次 all-reduce，逻辑正确，待多卡实测。
- **LHUCTaskTower 字段重复**：与 `TaskTower`/`BayesTaskTower` 字段重复，proto2 下属可接受的安全做法（避免跨文件搬移 message 导致 `_pb2` import 路径断裂）。

## 2026-07-20 (rev2): bias 特征改用 feature_group 逻辑视图

### 修改动机

初版每塔 bias 特征通过 `lhuc_gate { bias_feature_names: ... }` 列名 + 运行时从主 group 拼接张量按 offset 切片（`_extract_tower_bias`）实现。鉴于 tzrec 中 **feature_group 本质是逻辑视图**（embedding 参数归 feature 所有，同 feature 跨 group 共享同一张表，与 PEPNet 的 `"domain"`/`"uia"` 用法一致），继续用"列名 + 切片"是重复造轮子且把 bias 特征错误地约束在主 group 内。

### 改动内容

1. **Proto**：`LHUCTaskTower` 新增 `optional string bias_feature_group = 17;`（非破坏性）。`LHUCEPGateConfig` 未改动（DBMTL_LHUC 等仍用 `bias_feature_names`）。
2. **模型** (`tzrec/models/mtl_lhuc.py`)：
   - 删除 `_bias_feature_dims` 与 `_extract_tower_bias`（offset 切片路径）。
   - 新增 `self._bias_group: Dict[str, str]`；`bias_dim = embedding_group.group_total_dim(bias_feature_group)`。
   - `predict()` 改为 `bias_embs[t] = grouped_features[self._bias_group[t]]`，照搬 PEPNet 模式。
   - 校验：设了 `lhuc_gate`/`lhuc_pp_net` 就必须设 `bias_feature_group`。
3. **Config / 测试 / 文档** 同步迁移到新形态。

### 收益

- 删除手工切片，特征顺序与维度由 `EmbeddingGroup` 原生保证。
- bias 特征不再受限于主 group，可引用任意已声明 feature。
- 与 PEPNet 配置语义统一。
