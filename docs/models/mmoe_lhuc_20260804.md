# MMOE_LHUC 模型改进记录

## 2026-08-04: 新增 MMOE_LHUC 模型（DCN+DNN → 单层 MMoE → 每塔 LHUC task tower，LHUC 门控感知专家路由）

### 一、修改背景

生产排序模型 `DBMTL_AFP_LHUC_CGC` 的结构为：

```
(dcnv2 ‖ dnn) → concat → LHUC EP gate(bias) → AFP → LHUC PPNet → stacked CGC → DBMTL BayesTaskTower
```

在 home-feed 排序场景暴露出几个可改进点：

1. **耦合 DBMTL concat 任务依赖**（`BayesTaskTower` + `relation_mlp`），但实际点击 / 转化之间不一定需要显式 concat 依赖，且 DBMTL 依赖要求父塔先于子塔声明，配置不灵活。
2. **专家层用 stacked CGC/PLE**，参数量大；在专家路由这一显式信号上没有与个性化门控联动。
3. **LHUC 仅作为共享前置门控**（模型级），不是真正的 task tower；所有任务塔共用同一组 bias 特征，无法为 CTR / CVR 塔分别建模个性化偏好，也无法分别接入 AFP。
4. **AFP 为模型级共享**，无法让某些塔用 AFP、某些塔不用。

本次改进据此提出新模型 **`MMOE_LHUC`**：

- **去掉 DBMTL**，任务塔独立（可选 ESMM / `task_space_indicator_label` 做漏斗建模）。
- 专家层用**经典单层 MMoE**（N 个共享专家 + 每 task softmax gate），参数更轻。
- **LHUC 作为 MMoE 的 task tower**：每个塔独立 `LHUCEPGate` + `LHUCPPNet`。
- **每个 LHUC task tower 支持不同的 bias feature group**（per-tower `bias_feature_group`）。
- **MMoE 每 task 的 softmax gate 权重向量拼入该塔 EP gate 的 bias embedding**，让个性化门控感知专家路由分布。
- **PPNet 的 gate_input 可配**：AFP(task_rep) 的 S 流（APPNet 风格）或与 EP gate 同源的 `cat(bias, gate)`（默认）。
- **bias group / LHUC gate / LHUC PPNet / AFP 全部 per-tower 独享、可自定义**。

### 二、模型结构

```
grouped_features["all"]  (net, dim F)
   ├── (可选) mask_net
   ├── bias_embs_i = grouped_features[bias_feature_group_i]   # 每塔独立 group
   │
   ├── DCNv2(net) → LayerNorm   ┐
   ├── bottom_mlp(net) → LN     ┘ concat → rep (dim D)
   │
   └── MMoE(rep):  单层，N 个共享专家 + 每 task softmax gate
         experts_k = MLP_k(rep)                  # k=1..N, out dim E
         for task i:
           gate_i = softmax(Linear_i(rep))       # [B, N]  ← per-task 路由分布
           task_rep_i = Σ_k gate_ik · experts_k  # [B, E]

   for task i:                                   # ───── LHUC task tower ─────
     ep_in_i = cat(bias_embs_i, gate_i)          # [B, B_i + N]  gate 注入 bias
     x = task_rep_i · LHUCEPGate_i(ep_in_i)      # EP 个性化 (input_dim=E)
     if LHUCPPNet_i:
        afp 模式:   S, O = AFP_i(x); x = LHUCPPNet_i(O, S)   # x=O, gate_input=S
        bias 模式:  x = LHUCPPNet_i(x, ep_in_i)              # gate_input=cat(bias,gate)（默认）
     x = task_mlp_i(x)   (可选)
     logits_i = Linear_i(x)
   bias_tasks (仅训练) / ESMM CTCVR / fused-weight loss
```

### 三、设计决策（已与需求方确认）

| 决策点 | 选择 | 说明 |
|---|---|---|
| 专家层结构 | 经典单层 MMoE | N 共享专家 + 每 task softmax gate，不堆叠 CGC |
| gate 注入 EP bias | gate 权重向量拼接到 bias embedding | `gate_input = cat(bias_embs, gate)`，让 EP 感知路由分布 |
| PPNet gate_input | per-tower oneof：AFP / bias | `pp_afp`·`pp_afp_soft` = AFP 的 S 流；unset = 同 EP 的 `cat(bias,gate)` |
| 落地方式 | 新建 `MMOE_LHUC`（proto tag 216） | 不改动现有模型与 v4* 配置 |
| bias/gate/ppnet/AFP 归属 | 全部 per-tower 独享 | 每个 tower 自定义自己的 group、gate、ppnet、AFP |

> AFP 模式下 LHUCPPNet 的输入是 AFP 的 **(O, S)**（O 作主网络输入 x，S 作 gate_input），与 `DBMTL_AFP_LHUC_CGC` 的 `s,o=afp(rep); rep=pp_net(o,s)` 保持一致。

### 五、Proto 定义要点

```proto
message MMOELHUCTaskTower {
    required string tower_name = 1;
    required string label_name = 2;
    repeated MetricConfig metrics = 3;
    repeated TrainMetricConfig train_metrics = 20;
    repeated LossConfig losses = 4;
    optional uint32 num_class = 5 [default = 1];
    optional MLP mlp = 6;                 // PPNet 之后的 task MLP（可选）
    optional float weight = 7 [default = 1.0];
    optional string sample_weight_name = 8;
    optional string task_space_indicator_label = 9;   // CVR 空间掩码
    optional float in_task_space_weight = 10 [default = 1.0];
    optional float out_task_space_weight = 11 [default = 1.0];
    required string bias_feature_group = 12;          // 每塔独立 bias group
    optional LHUCEPGateConfig lhuc_gate = 13;         // 每塔独立 EP gate
    optional LHUCPPNetConfig lhuc_pp_net = 14;        // 每塔独立 PP net
    oneof pp_gate_kind {                               // 每塔独立 AFP
        AFPConfig pp_afp = 15;
        AFPSoftConfig pp_afp_soft = 16;
    }
}

message MMOE_LHUC {
    optional MaskNetModule mask_net = 1;
    optional MLP bottom_mlp = 2;          // DNN 分支（与 dcnv2 并行）
    required CrossV2 dcnv2 = 3;
    required MLP expert_mlp = 4;          // MMoE 共享专家
    optional MLP gate_mlp = 5;
    required uint32 num_expert = 6 [default = 3];
    reserved 7, 8, 9, 10;                 // 原 model 级 gate/ppnet/afp，已下沉到 tower
    reserved "lhuc_gate", "lhuc_pp_net", "pp_afp", "pp_afp_soft";
    repeated MMOELHUCTaskTower task_towers = 11;
    optional ESMMConfig esmm = 12;
    optional SampleWeightFusion sample_weight_fusion = 13;
    repeated BiasTask bias_tasks = 14;
    optional PCGradConfig pcgrad = 15;
}
```

> 注意：`LHUCEPGateConfig.bias_feature_names` 在本模型中**不使用**——bias 来自每塔 `bias_feature_group` 的拼接 embedding 加上 MMoE gate 权重。

### 六、复用与新增

**复用（未改动语义）**：
- `LHUCEPGate` / `LHUCPPNet`（`tzrec/modules/lhuc.py`）
- `AFPModule`（hard STE）/ `AFPModule2`（soft，带熵正则 aux loss）（`tzrec/modules/afp*.py`）
- `CrossV2`、`MLP`、`MaskNetModule`
- `MultiTaskRank` 的 loss / metric 机制；`_compute_fused_weight`（自 `dbmtl_lhuc`）
- ESMM / BiasTask / sample_weight_fusion / pcgrad 的 loss 逻辑搬运自 `mtl_lhuc` 与 `dbmtl_afp_lhuc_cgc`

**改动**：
- `tzrec/modules/mmoe.py::MMoE.forward` 新增 `return_gates=False` 形参，True 时额外返回每 task 的 softmax 门控权重向量 `[B, num_expert]`；默认行为不变，现有 `MMoE` 模型不受影响。

### 七、配置示例（v1）

```protobuf
mmoe_lhuc {
    bottom_mlp { hidden_units: [512,256,128,64,32] dropout_ratio: 0.1 use_ln: true }
    dcnv2 { cross_num: 5 low_rank: 256 }
    expert_mlp { hidden_units: [512, 256] use_ln: true }
    num_expert: 4
    task_towers {
        tower_name: "is_click"     label_name: "is_click"     weight: 8.5
        bias_feature_group: "bias"
        lhuc_gate { hidden_units: 256 hidden_units: 128 hidden_units: 64 }
        lhuc_pp_net { hidden_units: [256,256,256,256] lhuc_hidden_units: 256 activation: "nn.ReLU" }
        pp_afp { mode: BIT_WISE threshold: 0.95 use_layer_norm: false }   # hard AFP
        losses { binary_cross_entropy {} }  metrics { auc {} }  train_metrics { auc {} }
    }
    task_towers {
        tower_name: "is_conversion" label_name: "is_conversion" weight: 1.0
        bias_feature_group: "bias"
        lhuc_gate { hidden_units: 256 hidden_units: 128 hidden_units: 64 }
        lhuc_pp_net { hidden_units: [256,256,256,256] lhuc_hidden_units: 256 }
        pp_afp { mode: BIT_WISE threshold: 0.95 use_layer_norm: false }
        losses { binary_cross_entropy {} }  metrics { auc {} }  train_metrics { auc {} }
    }
}
# model_config 顶层需新增 bias feature group（特征可与主组重叠，embedding 共享）
feature_groups { group_name: "bias" feature_names: "..." }
```

#### AFP 配置（per-tower，二选一，且必须配 `lhuc_pp_net`）

- **soft（`AFPModule2`，可微，带 `afp_entropy_p_loss` aux）**：
  ```protobuf
  pp_afp_soft { mode: BIT_WISE gate_hidden_units: 64 gate_hidden_units: 32
                temperature: 1.0 entropy_reg_weight: 0.05 use_layer_norm: false }
  ```
- **hard（`AFPModule`，STE，无 aux）**：
  ```protobuf
  pp_afp { mode: BIT_WISE threshold: 0.95 use_layer_norm: false }
  ```
- 不写 `pp_afp*` → PPNet 走默认 bias 模式 `LHUCPPNet(x, cat(bias, gate))`。

#### CVR 点击空间掩码（替代 ESMM 的另一种漏斗建模）

```protobuf
# conversion tower
task_space_indicator_label: "is_click"
in_task_space_weight: 1
out_task_space_weight: 0     # CVR 仅在被点击样本上监督
```

> 与 ESMM 二选一。若 model 级配了 `sample_weight_fusion`，会走 fused-weight 分支、绕过 `_tower_loss`，此时 `task_space_indicator_label` 不生效。

### 八、`hidden_units` vs `lhuc_hidden_units`（PPNet）

| 字段 | 作用 |
|---|---|
| `hidden_units` (`nn_dims`) | **主网络（被门控的 DNN）** 各隐层宽度；输出 = `hidden_units[-1]` |
| `lhuc_hidden_units` (`lhuc_dims`) | **门控 MLP** 的隐层宽度；每层门控 `gate_mlp = [lhuc_hidden_units..., 该层宽度]`，产出 `tanh` 缩放因子 |
